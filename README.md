# Topaz Corporate Website (English Version)

Чистий, адаптивний, оптимізований веб-сайт телекомунікаційної інфраструктури **Topaz** (англійська версія, збережена з [topaz.jp](https://topaz.jp/index)).

Проект реалізований як сучасний статичний Single Page Application (SPA) без жодних зовнішніх збирачів (Webpack/Vite/Bun не потрібні). Він готовий до завантаження на GitHub та публікації на будь-якому власному хостингу.

## ✏️ Як легко змінювати наповнення (без ризику зламати дизайн)

Всі тексти, назви, списки послуг, характеристики та контакти винесені в один зручний конфігураційний файл:
👉 [`js/content.js`](file:///Users/i/Projects/WebSite/js/content.js)

### 1. Зміна послуг (Services)
У `js/content.js` в об'єкті `services` кожна послуга має чітку структуру:
```javascript
voice: {
  title: "International Voice",
  lead: "Опис послуги...",
  summary: "Короткий анонс для картки на головній...",
  uses: [
    "Сценарій використання 1",
    "Сценарій використання 2"
  ],
  features: [
    { t: "Назва фічі", d: "Детальний опис фічі..." }
  ],
  specs: [
    { k: "Delivery", v: "SIP trunking (wholesale)" }
  ]
}
```
Ви можете вільно змінювати текст, додавати нові характеристики або пункти — сітка та оформлення автоматично підлаштуються.

### 2. Зміна контактних даних та реквізитів
У `js/content.js` відредагуйте:
- `brand.tagline` — слоган компанії.
- `brand.locations` — перелік міст/датацентрів.
- `company.rows` — рядки таблиці профілю компанії (адреса, рік заснування, напрямки тощо).

### 3. Зміна кольорової гами
У файлі [`css/style.css`](file:///Users/i/Projects/WebSite/css/style.css) зверху розташовані змінні:
```css
:root {
  --tc: #69B7B5;        /* Основний фірмовий бірюзовий колір */
  --tcd: #38716F;       /* Темніший відтінок для ховерів */
  --tcl: #F0F8F7;       /* Світлий фоновий відтінок */
  --tkd: #0D1615;       /* Темний фон блоків Hero та футера */
}
```
Зміна значення `--tc` змінить акцентний колір на всьому сайті водночас.

## 💻 Як відкрити та тестувати на комп'ютері

Оскільки сайт повністю статичний, є два найпростіших способи:

### Варіант А: Подвійний клік
Просто відкрийте файл `index.html` у вашому браузері (Chrome, Safari, Firefox, Edge).

### Варіант Б: Локальний веб-сервер
У терміналі в папці проекту виконайте:
```bash
python3 -m http.server 8000
```
Після цього відкрийте в браузері: `http://localhost:8000`

## 🌐 Як опублікувати на хостинг

Сайт складається виключно зі статичних файлів (`.html`, `.css`, `.js`, `.svg`), тому його підтримує **будь-який хостинг у світі**:

### 1. Безкоштовно на GitHub Pages
1. У вашому GitHub репозиторії перейдіть у **Settings** → **Pages**.
2. У пункті **Build and deployment** виберіть джерело: **GitHub Actions** (робочий процес `.github/workflows/deploy.yml` уже налаштовано в проекті) або **Deploy from a branch** (`main` / root).
3. Через 1-2 хвилини ваш сайт буде доступний за адресою: `https://YOUR_USERNAME.github.io/REPO_NAME/`.

### 2. Безкоштовно на Netlify або Vercel
- **Netlify**: перетягніть папку проекту у вікно `app.netlify.com/drop` — сайт опублікується за 5 секунд.
- **Vercel**: підключіть ваш GitHub репозиторій, налаштування залишаються за замовчуванням (Zero Config).

### 3. На власний VPS / VDS / виділений сервер (Nginx або Apache)
Просто скопіюйте всі файли у кореневу директорію вашого веб-сервера (наприклад, `/var/www/html/`):
```bash
rsync -avz --exclude='.git' /Users/i/Projects/WebSite/ user@your-server-ip:/var/www/html/
```

### 4. На звичайний віртуальний хостинг (cPanel, DirectAdmin, FTP)
Завантажте вміст папки проекту в папку `public_html` через FTP-клієнт (FileZilla, Cyberduck) або менеджер файлів хостингу.

## ⚡ Оптимізації, виконані в цьому проекті:
- **Чиста англійська мова**: видалено всі японські фрагменти та зайвий бандл.
- **Легковажність**: розмір зменшено з ~10 МБ до кількох десятків кілобайт (шрифт `IBM Plex Sans JP` підключається динамічно через Google Fonts CDN).
- **Плавна навігація (Hash Routing)**: посилання на послуги (`#service/voice`, `#service/sms`, `#contact`) працюють стабільно на будь-якому сервері без необхідності налаштування складних правил `.htaccess` чи `nginx.conf`.
- **Безпечна зміна даних**: логіка та стилі відокремлені від тексту в `content.js`.
